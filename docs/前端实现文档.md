## 二、前端

实现两个角色入口、两套页面布局：

1. **管理员端（Admin）**：教室管理查询、课程管理查询、预约审核
2. **使用者端（User）**：教室查询、课程查询、教室预约（教师与学生共用，按登录身份展示差异）

相关的三个核心功能对应关系：

| 功能 | 管理员端 | 使用者端 |
| --- | --- | --- |
| 教室管理查询 | 增删改查 + 状态维护 + 设备关联查看 | 只读查询 + 空闲教室筛选 |
| 课程管理查询 | 增删改查 + 排课管理 | 只读查询（按教师/教室/星期筛选） |
| 教室预约 | 审核预约、查看全部预约 | 提交预约、查看/取消自己的预约 |

## 五、角色与路由设计

### 5.1 角色定义（对齐数据库 `User.role`）

| 角色值 | 中文 | 进入端 |
| --- | --- | --- |
| `ADMIN` | 管理员 | 管理员端 |
| `TEACHER` | 教师 | 使用者端 |
| `STUDENT` | 学生 | 使用者端 |

### 5.2 路由表

| 路径 | 页面 | 权限 |
| --- | --- | --- |
| `/login` | 登录页 | 公开 |
| `/admin` | 管理员首页（概览） | ADMIN |
| `/admin/classrooms` | 教室管理 | ADMIN |
| `/admin/courses` | 课程管理（含排课） | ADMIN |
| `/admin/reservations` | 预约审核 | ADMIN |
| `/user` | 使用者首页 | TEACHER / STUDENT |
| `/user/classrooms` | 教室查询 | TEACHER / STUDENT |
| `/user/courses` | 课程查询 | TEACHER / STUDENT |
| `/user/reservations` | 我的预约 | TEACHER / STUDENT |

### 5.3 路由守卫逻辑

```text
登录成功 → 读取 user.role
  ├─ ADMIN      → 跳转 /admin
  └─ TEACHER/STUDENT → 跳转 /user

未登录访问受保护路由 → 重定向 /login
角色不匹配 → 403 提示页或重定向到对应端首页
```

### 6.2 管理员端

#### 6.2.1 教室管理 `/admin/classrooms`

**查询区（筛选）**

| 筛选项 | 字段 | 类型 |
| --- | --- | --- |
| 楼宇 | `building` | 输入框 |
| 房间号 | `room_number` | 输入框 |
| 容量下限 | `capacity` | 数字 |
| 楼层 | `floor` | 数字 |
| 状态 | `status` | 下拉：AVAILABLE / MAINTENANCE |

**列表区（表格）**

| 列名 | 字段 | 说明 |
| --- | --- | --- |
| 教室编号 | `classroom_id` | 主键 |
| 楼宇 | `building` | |
| 房间号 | `room_number` | 展示为「A-101」 |
| 容量 | `capacity` | |
| 楼层 | `floor` | |
| 状态 | `status` | 标签：可用 / 维护中 |
| 设备 | — | 展开行或弹窗，读取 `Classroom_Device` + `Device` |
| 操作 | — | 编辑、删除、切换状态 |

**操作区**

- 【新增教室】弹窗表单
- 【编辑】回显并提交
- 【删除】二次确认（需后端检查是否有关联排课/预约）
- 【查看设备】侧栏展示该教室设备清单

**表单校验**

- `building`、`room_number` 必填
- `capacity > 0`
- `floor >= 0`
- 同楼宇下房间号不可重复（后端返回错误时前端展示）

#### 6.2.2 课程管理 `/admin/courses`

本页包含 **课程基本信息** 与 **排课** 。

##### Tab 1：课程列表

**查询区**

| 筛选项 | 字段 |
| --- | --- |

**列表区**

| 列名 | 字段 |

**操作**

- 新增课程：选择教师（`role=TEACHER` 的用户）+ 课程名
- 编辑 / 删除课程

##### Tab 2：排课管理（可在课程行点击进入，或统一列表）

**查询区**

| 筛选项 | 字段 |
| --- | --- |
| 课程 | `course_id` |
| 教室 | `classroom_id` |
| 星期 | `weekday` |
| 周次 | `start_week` ~ `end_week` |

**列表区**

| 列名 | 字段 | 展示格式 |
| --- | --- | --- |
| 排课编号 | `schedule_id` | |
| 课程名称 | `course_name` | 关联 |
| 教师 | `teacher_name` | 关联 |
| 教室 | `building` + `room_number` | 关联 |
| 星期 | `weekday` | 周一~周日 |
| 节次 | `start_period` ~ `end_period` | 如「第3-4节」 |
| 周次 | `start_week` ~ `end_week` | 如「1-16周」 |
| 操作 | — | 编辑、删除 |

**新增/编辑排课表单校验**

- `weekday`：1-7
- `start_period`、`end_period`：1-13，且 `start <= end`
- `start_week <= end_week`，均 > 0
- 教室冲突由后端/触发器校验，前端展示错误信息

## 七、数据类型定义（TypeScript）

与数据库字段对齐，供参考：

```typescript
// 用户
interface User {
  user_id: string
  name: string
  phone?: string
  email?: string
  role: 'ADMIN' | 'TEACHER' | 'STUDENT'
  status: 'ACTIVE' | 'DISABLED'
}

// 教室
interface Classroom {
  classroom_id: number
  building: string
  room_number: string
  capacity: number
  floor: number
  status: 'AVAILABLE' | 'MAINTENANCE'
  devices?: ClassroomDevice[]  // 详情时返回
}

interface Device {
  device_id: number
  device_name: string
  device_type: string
  description?: string
}

interface ClassroomDevice {
  device_id: number
  device_name: string
  device_type: string
  quantity: number
}

// 课程
interface Course {
  course_id: number
  course_name: string
  teacher_id: string
  teacher_name?: string
}

// 排课
interface Schedule {
  schedule_id: number
  course_id: number
  course_name?: string
  teacher_name?: string
  classroom_id: number
  building?: string
  room_number?: string
  weekday: number       // 1-7
  start_period: number  // 1-13
  end_period: number
  start_week: number
  end_week: number
}

// 预约
interface Reservation {
  reservation_id: number
  user_id: string
  user_name?: string
  classroom_id: number
  building?: string
  room_number?: string
  reservation_date: string  // YYYY-MM-DD
  start_period: number
  end_period: number
  purpose: string
  apply_time: string
  status: 'PENDING' | 'APPROVED' | 'REJECTED' | 'CANCELLED'
  audit_comment?: string
}
```
