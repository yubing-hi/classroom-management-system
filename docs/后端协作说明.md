# 后端协作说明

---

## 一、协作总览

本项目前后端模式：

```text
浏览器 (Vue 3 前端)  →  HTTP /api/*  →  Flask 后端 (app/app.py)  →  MySQL
```

### 分工边界

| 负责人 | 目录 | 职责 |
| --- | --- | --- |
| 前端 | `frontend/` | 页面、路由、调用 API |
| 后端 | `app/` | 提供 REST API、业务逻辑、连接数据库 |
| 数据库 | `sql/` | 建表、触发器、视图、统计查询 |

### 当前进度

| 模块 | 状态 | 说明 |
| --- | --- | --- |
| 数据库表结构 | 已完成 | `sql/create_tables.sql` |
| 测试数据 | 已完成 | 后续同学可用classroom.db补充 |
| Flask API | 已实现 | `app/app.py`，前端可直接联调 |
| 触发器 | 待补充 | `sql/triggers.sql` 仍为占位 |
| 视图 | 待补充 | `sql/views.sql` 仍为占位 |
| 统计查询 | 待补充 | `sql/queries.sql` 仍为占位 |

> 后端同学不需要从零写 API，而是在现有 `app/app.py` 基础上维护、扩展。  
> 若你修改了接口路径或字段，需要同步告知前端，更新本文档。

## 二、本地环境搭建

### 2.1 前置条件

- MySQL 8.x
- Python 3.11+（推荐 3.11；3.14 亦可）

### 2.2 安装 Python 依赖

```bash
cd classroom-management-system
conda create -n cms-env python=3.11 -y  
conda activate cms-env
pip install -r app/requirements.txt
```

依赖清单（`app/requirements.txt`）：

```text
pymysql
python-dotenv
flask
flask-cors
PyJWT
```

### 2.3 配置数据库连接

复制环境变量文件：

```bash
copy .env.example .env
```

编辑 `.env`（**不要提交到 Git**）：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的密码
DB_NAME=classroom_management
```

可选：

```env
JWT_SECRET=自定义密钥
```

### 2.4 初始化数据库

**第一步：建库建表**

```bash
mysql -u root -p < sql/create_tables.sql
```

**第二步：导入测试数据**

Windows 下直接用 `mysql < sql/insert_test_data.sql` 可能出现中文乱码，请改用：

```bash
cd app
python seed_data.py
```

**第三步：验证连接**

```bash
python app/db_connect.py
# 期望输出：数据库连接成功: (1,)
```

### 2.5 启动后端

```bash
cd app
python app.py
```

默认监听：`http://localhost:5000`

前端开发服务器：`http://localhost:5173`

## 三、相关约定约定

### 3.1 统一响应格式

所有接口必须返回如下 JSON 结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| 字段 | 说明 |
| --- | --- |
| `code` | `0` 表示成功，非 `0` 表示失败 |
| `message` | 成功时为 `"success"`，失败时为中文错误说明 |
| `data` | 业务数据；失败时可为 `null` |

前端已在 `frontend/src/utils/request.ts` 中统一处理：

- `code !== 0` → 弹出 `message` 错误提示
- HTTP `401` → 自动跳转登录页

**请勿随意更改此结构**，否则前端所有页面会报错。

### 3.2 认证方式

| 项目 | 约定 |
| --- | --- |
| 登录 | `POST /api/auth/login`，body: `{ user_id, password }` |
| 令牌 | JWT，放在请求头 `Authorization: Bearer <token>` |
| 有效期 | 默认 24 小时 |
| 获取当前用户 | `GET /api/auth/me` |

登录成功响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOi...",
    "user": {
      "user_id": "9001",
      "name": "管理员",
      "role": "ADMIN",
      "status": "ACTIVE"
    }
  }
}
```

### 3.3 角色与权限

| role 值 | 说明 | 可访问接口 |
| --- | --- | --- |
| `ADMIN` | 管理员 | 全部接口 |
| `TEACHER` | 教师 | 查询类 + 预约（不可访问 `/api/classrooms` POST/PUT/DELETE 等管理接口） |
| `STUDENT` | 学生 | 同教师 |

权限装饰器（`app/app.py` 中已有）：

- `@login_required`：需登录
- `@admin_required`：仅管理员

### 3.4 跨域

后端已启用 `flask-cors`，允许前端 `localhost:5173` 访问。

前端代理配置（`frontend/vite.config.ts`）：

```ts
proxy: { '/api': { target: 'http://localhost:5000', changeOrigin: true } }
```

前端环境变量（`frontend/.env.development`）：

```env
VITE_API_BASE_URL=http://localhost:5000/api
```

### 3.5 分页约定

列表接口统一支持：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `page` | 1 | 页码 |
| `page_size` | 10 | 每页条数 |

列表响应 `data` 结构：

```json
{
  "items": [],
  "total": 100,
  "page": 1,
  "page_size": 10
}
```

## 四、API 接口清单

> 以下接口均在 `app/app.py` 中实现。修改时请保持路径和字段名不变。

### 4.1 认证

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/auth/login` | 公开 | 登录 |
| GET | `/api/auth/me` | 登录 | 当前用户信息 |
| POST | `/api/auth/logout` | 公开 | 退出（前端清除本地 token） |

### 4.2 教室

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/classrooms` | 登录 | 教室列表（含设备） |
| GET | `/api/classrooms/available` | 登录 | 空闲教室查询 |
| GET | `/api/classrooms/:id` | 登录 | 教室详情 |
| POST | `/api/classrooms` | 管理员 | 新增教室 |
| PUT | `/api/classrooms/:id` | 管理员 | 更新教室 |
| DELETE | `/api/classrooms/:id` | 管理员 | 删除教室 |

**GET `/api/classrooms` 查询参数**

```text
building, room_number, capacity_min, floor, status, page, page_size
```

**GET `/api/classrooms/available` 查询参数（必填 date、start_period、end_period）**

```text
date, start_period, end_period, capacity_min, building
```

**教室对象字段**

```json
{
  "classroom_id": 1,
  "building": "A",
  "room_number": "101",
  "capacity": 120,
  "floor": 1,
  "status": "AVAILABLE",
  "devices": [
    { "device_id": 1, "device_name": "投影仪", "device_type": "多媒体", "quantity": 1 }
  ]
}
```

### 4.3 课程

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/courses` | 登录 | 课程列表 |
| POST | `/api/courses` | 管理员 | 新增课程 |
| PUT | `/api/courses/:id` | 管理员 | 更新课程 |
| DELETE | `/api/courses/:id` | 管理员 | 删除课程 |

**GET `/api/courses` 查询参数**

```text
course_name, teacher_id, page, page_size
```

**课程对象字段**

```json
{
  "course_id": 1,
  "course_name": "数据库系统",
  "teacher_id": "1001",
  "teacher_name": "张老师"
}
```

### 4.4 排课

### 4.5 预约

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/reservations` | 登录 | 管理员看全部；普通用户只看自己的 |
| POST | `/api/reservations` | 教师/学生 | 提交预约 |
| PUT | `/api/reservations/:id/cancel` | 本人 | 取消预约 |
| POST | `/api/reservations/:id/audit` | 管理员 | 审核预约 |

**POST `/api/reservations` 请求体**

```json
{
  "classroom_id": 1,
  "reservation_date": "2026-07-10",
  "start_period": 5,
  "end_period": 6,
  "purpose": "学生活动"
}
```

**POST `/api/reservations/:id/audit` 请求体**

```json
{
  "audit_result": "APPROVED",
  "audit_comment": "审核通过"
}
```

**预约对象字段**

```json
{
  "reservation_id": 1,
  "user_id": "2001",
  "user_name": "李学生",
  "classroom_id": 1,
  "building": "A",
  "room_number": "101",
  "reservation_date": "2026-07-10",
  "start_period": 5,
  "end_period": 6,
  "purpose": "学生社团活动",
  "apply_time": "2026-07-04 14:00:00",
  "status": "PENDING",
  "audit_comment": "审核通过"
}
```

`status` 枚举：`PENDING` / `APPROVED` / `REJECTED` / `CANCELLED`

## 五、相关任务

### 5.1 应遵守

1. **保持 API 契约不变**  
   路径、请求体字段名、响应 `data` 结构需与本文档及第四节一致。

2. **本地能跑通联调**  
   - `python app/db_connect.py` 成功  
   - `python app.py` 启动后，前端登录、查教室、预约、审核均正常

3. **错误信息用中文**  
   业务失败时 `message` 写清楚，例如：
   - `该时段教室有课程安排`
   - `该教室有关联排课，无法删除`

4. **如果要修改接口时请通知**

```bash

curl http://localhost:5000/api/classrooms ^
  -H "Authorization: Bearer TOKEN"
```
